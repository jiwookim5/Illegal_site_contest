# 훤히 — 공공 누리집 숨은 불법광고 점검 도구

공공 웹사이트에 숨겨진 불법광고(도박·성인·마약 등)를 찾아내는 Windows용 도구입니다.
'공공 웹사이트 불법광고 탐지 도구 개발 공모전' 출품작입니다.

**실행 파일만 필요하면** [Releases](https://github.com/CJ-AI-SecurityWave/hwonhi/releases)에서 `hwonhi.exe`를 받으세요. GitHub가 한글 파일 이름을 받지 않아 영문 이름으로 올라가 있으니, 받은 뒤 `훤히.exe`로 바꿔도 됩니다. Windows 전용입니다.

## 빠르게 시작하기

Windows 11, Python 3.12 이상, Microsoft Edge(기본 탑재)가 필요합니다.

```powershell
git clone https://github.com/CJ-AI-SecurityWave/hwonhi.git
cd hwonhi
python -m venv .venv
.venv\Scripts\python -m pip install --upgrade pip
.venv\Scripts\python -m pip install --require-hashes -r requirements.lock
```

그림 속 글자 인식까지 쓰려면 `winrt-*` 패키지도 설치합니다. 자세한 내용은 [빌드 매뉴얼](docs/빌드_매뉴얼.md) 4장을 보세요.
EXE를 빌드할 때는 `pyinstaller`도 설치합니다. 현재 잠금 파일은 기본 탐지·첨부파일 검사 의존성에 적용됩니다.
`playwright install`은 하지 않아도 됩니다. 탐지에는 시스템에 설치된 Edge를 씁니다.

### 소스에서 실행

```powershell
.venv\Scripts\python detector\main.py
```

CLI와 화면의 기본 탐색 범위는 최대 5000페이지, 실행 시간 상한은 25분입니다. 중지·시간 상한은 페이지 내부 작업에도 전달되며, 응답하지 않는 스캔은 5초 유예 후 해당 작업의 브라우저와 함께 종료합니다. 이때 마지막 저장까지의 부분 결과와 미완료 상태를 보여 줍니다. 게시글의 `page`·`pageIndex` 값이 다른 URL은 내용이 같아도 별도 페이지로 제출합니다.

화면의 점검 시간은 회차마다 25·50·120분 중 선택할 수 있습니다. 시간·페이지 한도에 도달하거나 사용자가 중지하면 **이어서 점검**으로 남은 주소부터 진행합니다. 앱을 종료했다가 다시 켜도 지난 점검 목록에서 재개할 수 있습니다. 완료 페이지는 건너뛰고, 도중에 중단된 페이지와 첨부파일·그림 검사 예산 때문에 미완료인 페이지는 다시 분석합니다. 완료한 파일 검사의 저장 결과는 재사용합니다.

재개한 결과에는 이전 회차의 검출을 합쳐 중복을 제거하며, 총 소요 시간과 회차를 표시합니다. 회차별 결과·증거는 별도 폴더에 보존합니다. 재개는 이전 설정과 당시 저장한 키워드 사전을 사용합니다. 탐지 코드가 바뀐 기록이나 재개 상태가 없는 구버전 기록은 새 점검이 필요합니다. 실행 중 시간 연장은 지원하지 않으며, 저장 후 다음 회차의 시간을 선택합니다. 자세한 저장 구조와 검증은 [재개 기능 보고서](docs/점검_재개_20261019.md)를 참고하십시오.

### 시험 사이트로 점검해 보기

`시험사이트 실행.bat`을 실행하면 시험 사이트 16개가 로컬에서 뜨고, 넣어 볼 주소 목록이 화면에 나옵니다.

> ⚠️ **실제 공공기관 누리집(go.kr 등)은 점검하지 마세요.** 허락 없이 크롤링하면 공격으로 보일 수 있습니다.
> 개발과 시험은 반드시 `127.0.0.1`의 시험 사이트에서만 합니다.

### 실행 파일 빌드

```powershell
pwsh -NoProfile -File tools\build.ps1 -OutputName hwonhi-local
```

위 명령의 결과물은 `dist\hwonhi-local\훤히\훤히.exe`입니다. 같은 출력 이름이 있으면 중단하며 기존 배포본을 삭제하지 않습니다. `-OutputName`을 생략하면 시각을 넣은 새 폴더를 만듭니다. 빌드한 실행 파일은 저장소에 커밋하지 않고 **GitHub Releases**에 올립니다.

## 검색엔진 보조 탐색

점검이 끝난 결과 화면의 **검색엔진에 노출된 광고도 찾아보시겠습니까? → 추가 탐색하기**에서 검색 결과에 노출된 대상 URL을 수집할 수 있습니다. 시작 화면에는 나오지 않으며, 대상 도메인은 점검 주소로 채워집니다. 검색 단어는 직접 입력하지 않고 광고 유형(도박·대포통장·마약 은어·성인·고수익 알바 등 7개 분류 25개 고정 단어)만 고르며, 이번 점검에서 찾은 단어를 더하거나 고급 설정에서 직접 추가할 수 있습니다. 검색 범위는 기본이 등록 도메인 전체(하위 도메인 포함)입니다. 광고로 판정한 노출은 `result_extra.json`에 `SEARCH_*_AD` 유형으로 합쳐집니다. 구글 검색은 SerpApi 키(`search.env`의 `SERPAPI_API_KEY`)가 필요하며, 키가 없어도 기본 점검은 그대로 동작합니다. 기본은 수집만 하며, 대상 URL 재검사는 별도로 선택합니다. 검색 API에는 도메인과 검색어가 전달되고 계정의 호출량을 사용합니다. 화면 오른쪽 위 **검색 API** 표시에서 API 연결 상태(정상·일부 오류·오류·키 없음)를 확인할 수 있습니다. 키 설정과 CLI 사용법은 [검색엔진 보조 탐색 사용법](docs/검색엔진_보조탐색_사용법.md)을 참고하세요.

## 판정 등급

결과 목록과 상세 화면, 보고서, CSV에는 광고로 판정한 항목마다 **확실(빨강)·의심(노랑)·경계(회색)** 등급과 근거 문장이 함께 표시됩니다. 등급은 광고 여부를 바꾸지 않으며 담당자의 검토 순서를 돕기 위한 것입니다. 확실은 불법 은어 키워드에 연락처·외부 주소나 숨김·위장이 겹친 경우, 경계는 판정 기준을 겨우 넘었거나 글 일부만 광고로 판정한 경우, 또는 아래의 광고 근거가 부족한 경우입니다. 대회 제출 파일(`result.json`·`result_extra.json`)에는 넣지 않습니다.

## 경계 · 제출 제외 항목과 제출 결과

광고로 확정할 근거가 부족한 문구는 **경계** 등급에 **제출 제외** 표시를 붙여 보여 줍니다(예전 이름 ‘검토 후보’). 정상 용도가 있는 재택부업·백링크 등의 표현, 서로 떨어진 문장의 단서를 합쳐야 기준을 넘는 문구, 정상 안내와 개인 연락처가 섞인 문구 등이 대상입니다. 이 항목은 결과 목록의 등급 필터에서 ‘경계’를 고르면 함께 보이고 보고서·CSV·점검 기록에 남지만, 제출용 `result.json`과 `result_extra.json`의 위반 항목에서는 제외됩니다. 조치 상태를 변경하는 것은 이 항목의 광고 확정이나 제출 승격을 뜻하지 않습니다. 기존 실행 기록의 판정은 자동으로 다시 계산하지 않으며, 예전에 ‘검토 후보’로 저장한 항목도 화면·보고서·CSV에서는 ‘경계 · 제출 제외’로 보입니다.

주소나 카톡 언급만으로 예방·독서·상담 문맥을 무효화하지 않습니다. 일반 홍보어의 가점은 최대 두 개로 제한하고, 가입 보너스·판매·충전 등 실제 유도는 별도로 봅니다. 문장 경계와 가까운 구간을 기준으로 단서를 결합하며, 예방 문구 옆에 독립적인 광고 문장이 있으면 해당 광고는 유지합니다. 이 규칙과 등급은 불법 여부의 법적 확정이나 확률을 의미하지 않습니다.

정책 검사는 `tools/test_precision_policy.py`, 후보의 저장·화면·CSV 검사는 `tools/test_ui_result_regressions.py`에 있습니다.

## 점검 기록 보존

CleanGov의 실행·증거 보존, 판정 규칙 기록, 조치 이력, CSV 출력 보호 방식을 훤히의 기존 탐지 구조에 적용했습니다.

- 점검마다 `runs/<실행 ID>/`에 결과, 실행 설정, 활성 키워드 사전과 소스 SHA-256을 저장합니다. GUI의 증거 사진(원본 코드 포함)·페이지 사본은 고급 설정에서 각각 켰을 때만 저장하며, 끈 점검의 결과 상세에는 해당 설정을 켜야 저장된다는 안내가 보입니다. 결과 화면에는 이번 점검에서 검사한 항목(기본 4종과 켠 추가 검사)도 함께 표시됩니다. CLI 사진은 `--evidence`를 켰을 때 저장합니다.
- 출력 폴더의 `result.json`·`result_extra.json`은 마지막 종료 실행의 제출용 사본(부분 점검 포함)입니다. 표준 스키마는 그대로입니다. 중간 결과는 해당 실행 폴더에 저장하므로 실행 예외나 첫 페이지를 열기 전 취소가 이전 제출 결과를 덮지 않습니다.
- 결과 화면의 **점검·조치 이력 보기**에서 실행 목록과 변경 전후 상태·메모를 확인합니다. 조치 상태와 이력은 `review.sqlite3`에 함께 저장하며, 기존 `review_state.json`은 한 번 가져온 뒤 원본을 남깁니다.
- 오탐을 직접 확인한 페이지는 결과 상세의 **다음 점검에서 주소 제외**에서 사유와 확인 체크를 남겨 제외합니다. 같은 출력 폴더의 다음 점검·조치 확인·검색 결과 재검사에 적용되며, 상단 **점검 제외 목록**에서 해제할 수 있습니다. 기존 ‘오탐 처리’만으로는 검사를 생략하지 않습니다. 제외한 페이지의 내용 변경과 그 안에서만 연결된 페이지는 확인하지 않으며, 결과에 제외 수와 주소를 표시합니다.
- 첫 실행 때 이전 버전의 결과·증거는 `runs/legacy-import/`에 복사합니다. 손상된 조치 기록이나 불완전한 복사는 오류로 알립니다.
- 일반 링크 중 삭제·로그아웃 등 상태 변경 경로와 명시적인 동작 파라미터는 탐색 대기열에 넣지 않습니다.
- CSV에서 수식으로 해석될 수 있는 셀에는 작은따옴표를 붙입니다. 제출 JSON과 보존된 검출 원문은 바꾸지 않습니다.

시작 화면의 **지난 점검 결과**에서 저장한 결과를 다시 열거나 삭제할 수 있습니다. 삭제를 확인하면 해당 실행의 증거 사진과 페이지 사본도 함께 지워지며, 조치 변경 이력은 남습니다. 가장 최근 결과를 지우면 제출용 사본은 남은 실행 중 가장 최근 결과로 바뀝니다. 기록 폴더는 자동 삭제하지 않습니다. 백업은 앱을 종료한 뒤 출력 폴더 전체를 복사하십시오. 체크섬은 파일 변경·손상 확인용이며, 전자서명이나 변조 방지 저장소는 아닙니다.

```powershell
.venv\Scripts\python tools\verify_run.py "out\runs\<실행 ID>"
.venv\Scripts\python tools\test_persistence.py
.venv\Scripts\python tools\test_ui_history.py
```

## 정상 문맥과 복합 회귀

독서의 ‘토토’, 유리공예의 ‘바카라’, 공공 통계·회복 상담처럼 정상 용도가 확인된 문구는 제한된 약한 홍보어와 함께 있어도 광고로 확정하지 않습니다. 연락처·가입 보너스·거래 표현이 붙은 광고는 계속 판정합니다. 인용문·코드·표는 가까운 설명 제목과 실제 표시 상태를 확인하며, 숨김·링크에는 인용 예외를 적용하지 않습니다. 비활성 상담 탭은 연결된 ARIA 탭과 회복 제목을 함께 확인합니다.

노출된 ‘카지노 가입 보너스’와 구분자를 끼운 같은 문구도 추가 유형 `VISIBLE_AD(게시판 노출 광고)`로 탐지합니다. 숨김 광고와 문구가 같아도 다른 위치의 노출 광고는 유지하며, 숨김 자식의 문구를 부모의 노출 광고로 다시 보고하지 않습니다.

`::before`·`::after`가 생성한 일반 광고 문구도 같은 노출 광고 유형으로 보고하며, 결과에 CSS 위치를 적습니다. 생성 문구에 숨김·난독화 기법이 있으면 기존 기법 판정을 유지합니다.

```powershell
.venv\Scripts\python tools\test_complex_policy.py
.venv\Scripts\python tools\complex_precision.py --output _regress\complex-source-new
.venv\Scripts\python tools\complex_precision.py --exe dist\훤히\훤히.exe --output _regress\complex-exe-new
```

출력 경로는 새 폴더여야 합니다. 정상 51개·광고 6개를 고정한 합성 개발 자료이며, 독립 정확도 평가가 아닙니다. 자세한 범위와 검증 기록은 [빌드 매뉴얼](docs/빌드_매뉴얼.md)의 복합 페이지 회귀 절을 참고하세요.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `detector/` | 탐지 엔진과 화면(UI) |
| `tools/` | 시험 서버, 채점·회귀 점검, 빌드 스크립트 |
| `testsite*/` | 검증용 시험 사이트와 정답셋 |

모듈별 설명은 [빌드 매뉴얼](docs/빌드_매뉴얼.md) 3장에 있습니다.

## 실행 상태와 부분 결과

진행 화면은 분석한 페이지·대기 중인 주소·찾은 의심 항목(결과 목록과 같은 단위)·지난 시간과 점검 시간 상한을 표시하고, 열지 못한 페이지가 있으면 그 수를 덧붙입니다. 대기 주소는 지금까지 발견한 주소로, 탐색하면서 늘었다 줄었다 합니다. 전체 페이지 수가 확인되지 않으므로 완료 백분율은 표시하지 않습니다. 결과의 의심 항목은 담당자가 원문과 증거를 검토해야 하며 자동 판정만으로 불법광고가 확정되는 것은 아닙니다.

하단 상태줄은 실행 상태와 기록 위치를 표시합니다. 긴 기록 위치는 눌러 전체 경로를 확인할 수 있으며, 본문과 결과 목록은 상태줄 위에서 스크롤됩니다. **프로그램 종료**는 진행 중인 점검·검색·조치 확인을 멈추고 저장이 끝난 뒤 해당 앱 창을 닫습니다. 창의 X 버튼으로 닫아도 같은 정리 경로를 사용합니다. 일반 브라우저 탭으로 열린 경우 브라우저 설정에 따라 탭은 남을 수 있습니다.

스캔은 전용 프로세스에서 실행하고 Windows Job Object로 해당 브라우저만 관리합니다. 한 단계가 120초 넘게 진행되지 않으면 부분 결과로 종료합니다. 페이지마다 복구용 체크포인트를 원자적으로 저장하고, 제출 형식의 중간 사본은 주기적으로 갱신합니다. 강제 종료 뒤의 실행 기록은 원본을 덮어쓰지 않고 **완료 미확인 중간 기록**으로 열 수 있습니다. 엔진 기록 시간과 프로세스 종료 확인 시간은 별도입니다.

추가 로컬 검사:

```powershell
.venv\Scripts\python tools\test_public_site_fixes.py
.venv\Scripts\python tools\test_scan_control.py
.venv\Scripts\python tools\test_scan_ui_controls.py
```

### 정상 문맥 감점

‘예방·주의·안전’ 같은 단어만으로 광고 점수를 낮추지 않습니다. 예방·교육, 피해·상담 지원, 경고·신고 안내, 단속·보도 문맥을 구분해 의미군당 0.5점, 합계 최대 0.8점을 반영합니다. 반복 표현은 중복 감점하지 않으며 거래 유도가 없는 안내에는 별도의 정상 문맥 판정도 적용합니다. 실제 가입·입금 유도와 충돌하면 감점으로 지우지 않고 광고 또는 검토 후보로 남깁니다. 점수는 확률이 아닙니다.

공개 문서의 짧은 발췌와 합성 문구를 구분한 [시험 자료](docs/정상문맥_시험자료_20261018.md)는 `tools/check_context_corpus.py`로 오프라인 검사합니다. 개발용 소규모 자료이며 실제 누리집 전체 정확도를 뜻하지 않습니다. 링크 목적지를 자동으로 조회해 신뢰하는 기능은 포함하지 않습니다.

### 공모전 기준 검사와 시간 기록

GUI 기본값은 HOMOGLYPH·JAMO·TRANSPARENT·OFFSCREEN 4종 검사입니다. 여러 요소에 나눠 쓴 자모·닮은꼴 문장, iframe과 지연 삽입도 계속 검사합니다. **추가 광고 유형 검사**, 첨부파일·검색창·OCR·연계 링크·위장 검사는 선택할 수 있으며, 선택한 작업이 끝나야 완료됩니다. CLI는 기존 추가 유형 검사를 유지하며 GUI와 같은 주요 4종 경로는 `--primary-only`로 실행합니다.

완료 결과의 `meta.elapsed_sec`는 GUI 요청 수락/CLI 탐지 시작부터 준비·스캔·선택 검사·결과 저장·스키마 검증·증거 해시 계산을 포함합니다. 마지막 메타데이터 기록 직전 시점이며, 최종 파일 교체와 GUI 갱신 지연은 외부 관측 시간과 비교해 검증합니다. `last_result.json`의 `engine_elapsed`·`process_elapsed`는 별도로 남습니다. 중간 체크포인트는 아직 엔진 시간이며 완료 시간으로 보지 않습니다. 시간 상한·페이지 상한·사용자 중지와 대기열 잔량은 부분 결과로 표시합니다.

게시판·본문 링크 3개마다 일반 링크 1개를 배분합니다. 같은 페이지로 비교할 때 쿼리의 빈 값·추적 이름의 값과 경로 대소문자도 보존합니다. URL 변형 폭증은 별도의 탐색 제한과 미탐색 기록으로 관리하며, 제출 결과를 합쳐 없애지 않습니다.

`tools/test_contest_execution.py`는 타이머 취소, 실제 지연 삽입 보존, 탐색 공정성, URL 구분, 시간 및 스키마 실패 처리를 검사합니다. `tools/benchmark_contest_gui.py --before <기존EXE> --after <새EXE> --output <새폴더>`는 같은 로컬 스크롤·지연 광고 사이트를 각 3회 GUI 경로로 실행합니다. 이 수치는 실제 기관 전체 완료 시간의 개선율을 보장하지 않습니다.
