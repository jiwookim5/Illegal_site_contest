# 훤히 — 공공 누리집 숨은 불법광고 점검 도구

## 사용설명서

## 결과 파일 생성 경로

| 파일 | 생성 위치 |
|---|---|
| `result.json` | **구동 파일(`훤히.exe`)이 있는 폴더** |
| `result_extra.json` | 구동 파일이 있는 폴더 |
| `scan_coverage.json` | 구동 파일이 있는 폴더 (점검 범위: 열지 못한 페이지와 사유, 열지 않은 주소) |

화면에서 조치 상태나 점검 키워드를 바꾸면 같은 폴더에 `review.sqlite3`·`keyword_state.json`이 생깁니다. 기존 `review_state.json`은 한 번 가져오고 원본을 남깁니다.
화면 모드는 다음 실행 때 지난 결과를 다시 볼 수 있도록 `last_result.json` 을, 증거 사진과 점검 당시 페이지를
`runs/<실행 ID>/evidence/`·`snapshots/`에 남깁니다. 새로 점검해도 지난 결과와 사진·사본을 보존합니다.
결과 화면의 **점검·조치 이력 보기**에서 기록을 확인할 수 있습니다. 출력 폴더 전체를 백업하면 결과와 조치 이력도 함께 보존됩니다.

점검 도중에도 페이지 20개마다(직전 저장에서 최소 15초 뒤) 해당 실행 폴더에 `result.json`·`result_extra.json`을 씁니다. 도중에 프로그램이
꺼져도 그때까지 찾은 결과는 남습니다.

**열지 못한 페이지**: 시간 초과·접속 오류·서버 오류(5xx)로 열리지 않은 페이지는 대기열이 다 빈 뒤 한 번 더
열어 봅니다. 그래도 안 열리거나 접근이 거부(401·403·429)되면 사유와 함께 `scan_coverage.json` 과 화면·보고서의
'점검하지 못한 곳'에 남깁니다. **이 페이지들은 광고가 없는 것이 아니라 확인하지 못한 것입니다.** 페이지가 8개
잇달아 열리지 않으면(시간 초과·접속 오류·접근 거부) 서버가 막았거나 장애가 난 것으로 보고 점검을 멈춥니다(계속 요청하면 공격처럼 보일 수 있습니다).
서버 오류(5xx)는 값이 빠진 주소에 흔히 나오므로 이 계산에 넣지 않고, 실패로만 기록합니다.
최대 페이지 수에 닿아 열지 않은 주소도 함께 셉니다. 없는 주소(404 등)는 실패가 아니라 깨진 링크로 따로 보여 줍니다.

`--out <폴더>` 옵션을 주면 지정한 폴더에 생성됩니다. 옵션을 주지 않으면 위 기본 경로입니다.

검색엔진 추가 탐색(선택 기능, 3장) 결과도 추가 유형으로 제출합니다. 검색 실행별 파일은 `search_results/<실행폴더>/result_extra.json`에 저장하고, 같은 대상이면 위 `result_extra.json`에 기존 추가 결과를 보존하여 병합합니다. 전체 검색 후보·처리 기록인 `results.json`은 내부 기록이며 제출 JSON을 대신하지 않습니다. 현재 소스 GUI를 `--out out`으로 실행하면 프로젝트의 `out/result.json`·`out/result_extra.json`에 저장합니다.

## 상용 AI API 사용 여부

**사용하지 않습니다.**

본 도구의 기본 광고 판정은 외부 AI API를 호출하지 않으며 API 키가 필요하지 않습니다. 적격평가 대상인 기본 점검(`result.json`)은 키 없이 동작합니다.

선택 기능인 검색엔진 추가 탐색(3장)만 외부 검색결과 API를 씁니다. AI 모델은 쓰지 않습니다.

| 항목 | 내용 |
|---|---|
| 서비스 | SerpApi (구글 검색 결과 API, https://serpapi.com) |
| 모델 | 해당 없음 (AI 모델 아님, `engine=google`) |
| 환경변수 | `SERPAPI_API_KEY` |
| 설정 파일 | 구동 파일과 같은 폴더의 `search.env` (`search.env.example` 을 복사해 `SERPAPI_API_KEY=` 뒤에 키 입력). 환경변수가 있으면 환경변수가 우선 |
| 키 교체 | `search.env` 의 값만 바꾸면 되며 다시 빌드할 필요가 없음 |
| 전달되는 정보 | 검색할 도메인과 검색어. 검색 1회(페이지 1개)마다 계정 호출량 1건 사용 |

화면 오른쪽 위 **검색 API**에서 키를 입력하고 **저장 및 연결 확인**을 누르면 됩니다. 저장된 키는 다시 표시하지 않으며 **키 삭제**로 제거할 수 있습니다. **보기**는 현재 입력 중인 키만 표시합니다. 키는 로컬 `search.env`에 평문으로 저장되므로 해당 파일은 공유하지 마십시오.
기본 광고 판정에 필요한 모든 처리는 프로그램 내부에서 수행되므로, 기본 점검에서 인터넷 연결은 **점검 대상 누리집에
접속하는 용도로만** 사용됩니다. 폐쇄망에서도 대상 사이트에 접근 가능하다면 기본 점검은 동작합니다.
검색엔진 보조 탐색을 사용할 때만 위와 같이 SerpApi 서버에도 접속합니다.

## 1. 실행 방법

### 화면으로 실행 (기본)

1. `훤히.exe` 를 **더블클릭**합니다. 명령 프롬프트 창 없이 앱 창만 열립니다.
2. 시작 화면 가운데 입력란에 **점검 대상 진입 URL** 을 붙여넣습니다.
3. **점검 시작** 을 누릅니다(입력란에서 Enter 도 됩니다). 진행 상황 화면으로 바뀝니다.
4. 점검이 끝나면 결과 화면으로 바뀌고, 구동 파일과 같은 폴더에
   `result.json` 과 `result_extra.json` 이 생성됩니다.

검출 시간(`meta.elapsed_sec`)은 **점검 시작** 을 누른 때부터 **점검 완료** 까지입니다.

### 터미널로 실행 (자동화용 보조 기능)

여러 사이트를 연달아 점검하는 등 자동화가 필요할 때만 사용합니다.
화면 없이 점검하고 같은 결과 파일을 만듭니다.

```
훤히.exe --cli --url "https://점검대상주소"
```

> **PowerShell 에서는 아래처럼 실행하십시오.** `훤히.exe` 는 창 프로그램이라 PowerShell 이
> 끝나기를 기다리지 않고 바로 다음 줄로 넘어갑니다. `-Wait` 를 주면 점검이 끝난 뒤에 돌아옵니다.
>
> ```powershell
> Start-Process .\훤히.exe -ArgumentList '--cli','--url','https://점검대상주소' -Wait
> ```
>
> 이때 진행 상황은 새 창에 표시되고, 끝나면 그 창은 닫힙니다.

## 3. 화면 사용법

화면은 단계마다 그때 필요한 것만 보여 줍니다.

| 단계 | 보이는 것 |
|---|---|
| 시작 | 주소 입력란, **점검 시작**, 주소 입력란 아래 접혀 있는 **고급 설정**. 이전 결과가 있으면 **이전 결과 보기**(프로그램을 다시 켰을 때는 **지난 결과 보기**) |
| 점검 중 | 점검 중인 주소, 숫자 칸(분석한 페이지·대기 중인 주소·찾은 의심 항목·지난 시간/점검 시간), 진행 막대, 지금 보는 페이지, **점검 중지** |
| 결과 | 위쪽에 점검한 주소와 **다시 점검**, 왼쪽에 보기 탭·요약·보고서·결과 CSV, 가운데 검출 목록 |

**점검 중지**: 누르면 지금 보던 페이지까지 마치고 멈춘 뒤, 그때까지 찾은 결과를 보여 주고 결과 파일도 저장합니다.
첫 페이지를 열기 전에 멈추면 지난 결과를 그대로 둡니다. 점검이 25분을 넘으면 같은 방식으로 스스로 멈춥니다
(평가 상한 30분 안에 결과 파일을 쓰기 위함). 이렇게 일부만 점검한 결과에는 목록 위와 보고서에 그 사실이 표시되고,
지난 점검 목록과 결과 화면 위쪽 줄에는 이유가 짧게 붙습니다: **중지함**·**시간 초과로 중단**·**접속 막혀 중단**·**중간에 끊김**·
**페이지 한도 도달**(최대 페이지 수에 닿아 남은 주소가 있음)·**못 연 페이지 N건**.

**지난 결과 보기**: 프로그램을 껐다 켜도 마지막 점검 결과와 조치 상태를 다시 볼 수 있습니다.

오른쪽 위 **도움말** 버튼은 어느 단계에서나 사용 방법 창을, **점검 키워드** 버튼은 키워드 관리 화면으로 이동합니다. 왼쪽 탭 이름 아래에는 탭마다 무엇을 보여 주는지가 적혀 있습니다.
점검 중이거나 결과를 보다가 창을 새로고침해도 그 단계로 돌아옵니다.

### 점검 결과 탭

검출 항목을 페이지별로 묶어 보여줍니다. 항목마다 아래 정보가 함께 표시됩니다.

**공통 서식 광고 묶음**: 메뉴·하단·배너·위젯처럼 모든 페이지가 함께 쓰는 공통 서식(템플릿)에 광고가 심어지면,
같은 위치·같은 문구의 광고가 페이지마다 잡힙니다. 3개 이상 페이지에 똑같이 있는 광고는 목록 맨 위
'여러 페이지에 똑같이 들어 있는 광고'에 한 줄로 묶고, 몇 페이지에 있는지와 페이지 목록, 공통 서식에서 한 번에
지우라는 안내를 보여 줍니다. 묶인 줄의 오탐 처리·메모는 그 페이지들 모두에 함께 적용됩니다. 인쇄용 보고서도
같이 묶어 한 줄로 적고, 증거 사진은 한 번만 찍어 함께 씁니다. 결과 파일(`result.json`)과 CSV 에는 요강의
검출 단위(url + location + technique)에 맞춰 페이지마다 한 건씩 그대로 적습니다.

| 표시 | 의미 |
|---|---|
| 유형 배지 | 닮은꼴 글자 위장 / 자모 분해 / 투명 텍스트 / 화면 밖 은닉 / 추가 유형 이름. 주요 4종은 배지 아래에 그 기법이 무엇인지 한 줄 설명이 붙습니다 |
| 판정 근거 | 예: `전각 문자 9자 혼용`, `화면 밖 좌표 left:-9999px` |
| 검출 원문 | 실제로 심어져 있던 문자열 (변형 그대로) |
| 복원한 글자 | 난독화를 되돌린 문자열 |
| 광고로 본 근거 | 광고로 판단한 근거 표현 |
| 위치 | 숨긴 광고는 **숨김 풀어 보기**로 증거 사진, **누리집에서 보기**로 페이지 속 위치를 봅니다. 요소를 가리키는 CSS 선택자는 보고서와 CSV 에 적힙니다 |

**처리 상태**: 담당자가 원문과 증거를 살펴보고 `미확인 / 확인 / 오탐 처리`를 직접 선택합니다.
확인은 검토를 마쳤다는 뜻이며 광고 삭제를 자동으로 확인한 결과가 아닙니다. [조치 확인] 단추는 제거되었습니다.

**오탐 처리·메모**: 광고가 아닌 항목은 '오탐 처리'로 바꾸고, 항목마다 담당자 메모를 남길 수 있습니다.
이 정보는 `review.sqlite3`에 변경 전후 이력과 함께 저장되어 **다시 점검해도 유지**됩니다. 항목은 페이지·위치·유형·**문구**로
알아봅니다. 게시판에 글이 더해져 위치(순번)가 밀려도, 같은 페이지의 같은 문구를 오탐 처리했으면 그대로 이어받고
'오탐 처리 이어받음'으로 표시합니다. 반대로 오탐 처리한 자리에 다른 문구가 들어오면 새 항목으로 다시 알립니다.
확인 상태는 다음 점검에서 다시 검토하도록 이어받지 않습니다.

**오탐 확인 후 다음 점검에서 주소 제외**: 결과 상세의 **다음 점검에서 주소 제외**를 사용합니다.
직접 확인한 페이지를 고르고, 오탐 확인 사유를 입력한 뒤 확인 항목에 체크하고 **오탐 확인 · 이 주소 제외**를 누릅니다.
공통 서식으로 여러 페이지가 묶여 있어도 주소 하나씩 확인합니다. 선택한 항목의 오탐 상태, 주소 제외, 변경 이력은 함께 저장됩니다.
‘오탐 처리’만 선택하면 기존처럼 다음에도 검사하므로, 페이지 전체를 건너뛰려는 경우에만 주소 제외를 등록하십시오.

제외 범위는 **선택한 URL 전체**입니다. 경로 대소문자·끝 슬래시·쿼리와 값·http/https·포트가 다르면 다른 주소로 봅니다
(호스트 대소문자·기본 포트·`#` 뒤 위치 표시는 같은 주소로 봅니다). 다른 게시글이나 서브도메인을 한꺼번에 제외하지 않습니다.
해당 주소의 내용이 바뀌어도 검사하지 않으며, 그 페이지에서만 연결되는 하위 페이지는 발견하지 못할 수 있습니다.
등록된 주소는 직접 탐색·iframe 요청 전에 건너뜁니다. 다른 주소에서 HTTP 리다이렉트되면 브라우저가 제외 주소의 응답을
받을 수 있지만 본문 분석은 생략합니다. 제외는 접근 차단 규칙이 아니라 점검 범위 설정입니다.

상단 **점검 제외 목록**에서 주소·사유·등록 시각을 확인하고 **제외 해제**로 다시 검사 대상에 넣을 수 있습니다.
점검·검색 중에는 목록을 변경할 수 없습니다. 해제해도 과거 오탐 상태와 확인 이력은 남습니다.
같은 출력 폴더의 새 점검과 검색엔진 보조 탐색의 대상 URL 재검사에 적용됩니다. **이어서 점검은 원래 회차에 저장한 제외 목록을 유지합니다.** 변경한 제외 목록을 적용하려면 새 점검을 시작하십시오. 검색엔진의 수집 결과 자체는 보존합니다.
CLI 일반 점검도 같은 `--out` 폴더의 목록을 사용하며, 검색 보조 CLI는 `--review-dir <훤히 출력 폴더>`로 목록 위치를 지정합니다
(기본값: `--input` 결과 파일이 든 `search_results`의 상위 폴더 또는 `--out`의 상위 폴더. 목록 파일이 없으면 만들지 않고 제외 없이 진행합니다). 결과의 점검 범위 안내와 `scan_coverage.json`에는 제외 건수·주소·사유를, 실행 설정에는 적용한 목록을 남깁니다.
제외한 주소를 ‘확인’이나 ‘광고가 사라짐’으로 바꾸지는 않습니다. 제외한 iframe·첨부 등이 들어 있던 페이지는 검출 수가
줄었을 수 있으므로 그 페이지의 광고만 지난 점검 대비 ‘사라짐’ 비교에서 뺍니다. 다른 페이지는 평소처럼 비교합니다.

**결과 CSV 내려받기**: 검출 목록 전체를 엑셀에서 열 수 있는 형식으로 저장합니다. 마지막 열에 지난 점검 대비 '새로 생김'이 표시됩니다.

**보고서 보기·인쇄**: 결재·보고에 붙일 수 있는 한 장짜리 보고서를 새 창으로 엽니다. 점검 대상·일시·확인한 페이지 수,
유형별 건수, 조치 상태별 건수, 지난 점검과의 비교, 항목별 상세(위치·원문·증거 사진·조치 상태·메모)와 결재란이 들어갑니다.
**인쇄 · PDF로 저장** 단추로 종이로 출력하거나 PDF 로 저장합니다.

**지난 점검과 비교**: 같은 주소를 다시 점검하면 지난번에 없던 항목에 **새로 생김** 표시가 붙고, 지난번에 있었는데
이번에 보이지 않는 항목(지워졌거나 조치된 것으로 보이는 것)은 목록 위에 따로 모아 보여 줍니다. 왼쪽 요약에 두 수가 나오고,
**새로 생긴 것만** 확인란으로 새 항목만 볼 수 있습니다. 둘 중 한 번이라도 도중에 멈춘 점검이면
비교하지 않습니다.

**왼쪽 요약**: 찾은 광고 수, 광고가 있는 페이지 수, 아직 조치 안 한 항목 수, 지금 필터로 표시 중인 항목 수입니다.
지난 점검 결과가 있으면 새로 생긴 수와 사라진 수도 나옵니다.

**결과 거르기**: 목록 위쪽 검색 칸에 광고 문구나 페이지 주소 일부를 넣어 해당 항목만 봅니다.
**처리 상태**·**등급** 선택으로 미확인·확인·오탐 처리 항목이나 확실·의심·경계 항목만 볼 수 있습니다. 광고 근거가 부족해 제출에서 빠지는 항목은 ‘경계 · 제출 제외’로 표시되며 ‘경계’를 고르면 함께 보입니다.
결과를 열면 처리할 일이 남은 **미확인** 항목만 먼저 보이고, 오탐 처리·확인 항목은 목록 아래
**오탐 처리 N건 · 확인 M건 보기** 묶음에 접혀 있습니다. 펼치면 같은 표로 보이며 처리 상태를 되돌리거나 상세를 볼 수 있습니다.
미확인 항목이 하나도 없는 결과는 전체가 바로 보입니다. 접힌 항목도 요약 숫자, 보고서, CSV, 이력에는 그대로 들어갑니다.

**증거 보기·원본 소스 탭**: 숨긴 광고(주요 4종)만 나옵니다. 게시판 노출 광고나 검색창 점검 결과는 숨긴 것이 아니므로
증거 사진과 원본 코드가 없고, 점검 결과 탭에서 확인합니다.

**고급 설정**: 시작 화면의 **고급 설정** 을 펼치면 나옵니다. 항목 옆 **?** 를 누르면 설명이 나옵니다(최대 페이지, 천천히 점검, 첨부파일 검사,
검색창 점검, 서브도메인도 점검, 연계 링크 확인, 크롤러 위장 검사, 색인 목록). 기본값 그대로 두어도 됩니다.

**천천히 점검**: **실제 기관 누리집을 점검할 때는 켜십시오.** 페이지 사이에 0.7초씩 쉬고 `robots.txt` 가 막아 둔 주소는
건너뜁니다(터미널의 `--polite` 와 같음). 짧은 시간에 요청이 몰려 보안 관제에서 공격으로 오인되거나 서버에 부담을 주는 일을
막습니다. 300페이지 기준 3~4분쯤 더 걸립니다. 보고서의 '점검 방식' 칸에 이 설정이 기록되어, 대상 기관에 어떻게 점검했는지
설명할 때 쓸 수 있습니다. 시험용 누리집처럼 빠르게 끝내야 할 때는 꺼 두십시오(기본 꺼짐).

**점검 범위와 서브도메인**: 기본으로는 입력한 주소의 누리집만 봅니다. `www` 유무가 다른 주소(`xxx.go.kr` 와
`www.xxx.go.kr`)와, 진입 주소가 넘겨 준 주소(리다이렉트)는 같은 누리집으로 봅니다. **서브도메인도 점검** 을 켜면
같은 기관 도메인의 다른 주소(`bbs.xxx.go.kr`, `xxx.go.kr:8080` 등)로 이어지는 링크도 따라갑니다.
같은 서버에 함께 올라간 다른 기관 누리집(가상 호스트)은 점검 권한 밖이므로 켜도 따라가지 않습니다.

**연계 링크 확인** (기본 꺼짐): 누리집이 걸어 둔 바깥 링크(패밀리 사이트·배너·옛 행사 누리집 등)의 목적지가
도박·성인 광고 사이트로 바뀌지 않았는지 확인합니다(터미널의 `--check-links` 와 같음). 행사·사업 누리집의 도메인이
만료되면 광고 업자가 사들여 기관 링크를 광고 통로로 쓰는 일이 있는데, 기관 누리집 안은 바뀌지 않아 눈으로 알아채기 어렵습니다.
- 탐색이 끝난 뒤 바깥 **도메인마다 한 번만** 첫 화면 글자를 받아 판정합니다(링크한 주소가 없어졌으면 그 도메인 첫 화면을 한 번 더).
  목적지 안의 링크는 따라가지 않으므로 다른 누리집을 점검하는 기능이 아닙니다. 한 번에 50곳, 2분까지만 확인합니다.
- **브라우저로 열지 않습니다.** 광고 사이트의 스크립트가 담당자 PC 에서 실행되지 않고 그림도 받지 않습니다.
  그래서 스크립트로만 내용을 그리는 사이트는 광고를 놓칠 수 있습니다.
- 공공기관 도메인(`go.kr`·`korea.kr`·`ac.kr` 등)과 대형 서비스(네이버·유튜브·어도비 등)는 개인이 사거나 만료될 일이
  없으므로 조회하지 않습니다. 인터넷이 막힌 PC 에서는 결과가 나오지 않습니다.
- 목적지가 광고면 '피해 발생 또는 광고 확인됨', 도메인 판매·만료 안내 페이지이거나 도메인 주소 자체가 없으면 '주의'로 보고합니다.
  같은 링크가 여러 페이지(공통 하단 등)에 있으면 한 건으로 묶고 몇 곳에 더 있는지 적습니다.

**그림 속 글자 검사** (기본 꺼짐): 게시글·배너 그림을 받아 Windows 에 내장된 글자 인식(`Windows.Media.Ocr`, 한국어)으로
읽고, 광고 문구를 그림으로 만들어 올린 경우를 `IMAGE_TEXT_AD` 로 찾습니다(터미널의 `--ocr-images` 와 같음).
- 그림은 이 PC 안에서만 읽고 밖으로 보내지 않습니다. 상용 AI API·GPU 를 쓰지 않습니다.
- 같은 그림(공통 배너)은 한 번만 받아 읽고, 한 번의 점검에서 그림 200장·3분까지만 씁니다.
- 한국어 글자 인식 언어가 없는 PC(영어판 Windows 등)에서는 건너뛰고, 결과 화면의 점검 범위 안내에 그 사실을 적습니다.
- 첨부한 그림 파일(PNG·JPG·GIF·BMP)과 글자층 없이 그림만 든 스캔 PDF 는 이 설정과 관계없이 첨부파일 검사에서 읽습니다
  (스캔 PDF 는 크롬과 같은 PDF 엔진(PDFium)으로 페이지를 그림의 원래 해상도(최대 200dpi)로 그려 읽으므로 JPEG·팩스식 흑백 압축(CCITT)
  등 그림 형식과 관계없이 읽습니다. 한 문서에서 10쪽까지 읽습니다).

**크롤러 위장 검사**: 고급 설정의 체크박스를 켜면, 같은 주소를 검색엔진 크롤러 신원으로
한 번 더 조회해 응답이 달라지는지 확인합니다. 요청이 늘어 시간이 더 걸립니다.

**첨부파일 검사** (기본 꺼짐, 선택 시 검사): 게시글에 붙은 PDF·HWP·HWPX·DOCX·XLSX·PPTX·옛 형식 DOC·XLS·PPT 파일과 그림 파일, zip 묶음을 내려받아 본문에 숨은
광고 문구를 찾습니다. 파일은 글자만 읽고 열거나 실행하지 않으며, 20MB 가 넘는 파일은 받지 않습니다.
전자정부 표준프레임워크 게시판처럼 첨부를 `javascript:fn_egov_downFile(...)`·`onclick` 단추로 내려받는 경우도,
단추를 눌러 내려받기 주소만 알아낸 뒤 같은 방식으로 검사합니다(누르는 동안 페이지 이동은 취소하고, 삭제 같은
단추는 누르지 않으며, 숨은 폼 전송(POST)은 보내지 않고 같은 값을 GET 주소로 바꿔 받습니다).
문서 안에서 광고를 **흰 글씨·2pt 이하 글자·PDF 의 보이지 않는 글자(렌더 모드 3)**로 숨겼으면 판정 사유에
'문서 안에서 숨김: 흰 글씨' 처럼 숨긴 방식을 함께 적습니다(HWP·HWPX 는 글자 모양, PDF 는 채움색·글자 크기로 판단).
DOCX 는 Word 의 '숨긴 텍스트' 속성·흰 글씨·작은 글자를, PPTX 는 흰 글씨·작은 글자를, XLSX 는 숨긴 시트·숨긴 행과 열·흰 글꼴·작은 글꼴·
값을 안 보이게 하는 서식(`;;;`)을 봅니다. 옛 형식(97-2003) DOC·XLS·PPT 는 문서 속 글자열을 뽑아 판정하며, 숨긴 서식은 구분하지 않습니다.
zip 묶음은 안의 문서를 한 겹만 열어 같은 방식으로 검사하고(파일 30개·풀었을 때 합계 50MB 까지), 근거 문구에 안의 파일 이름을 적습니다.
스캔 문서는 그림 위에 보이지 않는 글자층을 덮어 두므로, 그림이 있는 PDF 페이지의 렌더 모드 3 은 숨김으로 보지 않습니다.

**검색창 점검** (기본 꺼짐, 선택 시 검사): 누리집의 검색창이 **검색결과 반사형 광고**에 악용될 수 있는지
미리 점검합니다. 악용자는 검색창에 광고 문구를 넣어 만든 검색결과 주소를 외부에 대량으로
링크해, 검색엔진이 그 주소를 기관 페이지로 색인하게 만듭니다. 그러면 도박 키워드 검색 결과에
기관 도메인이 광고 문구를 제목으로 달고 나타납니다. 서버에는 아무것도 저장되지 않아 게시판을
살펴봐도 흔적이 없습니다.

훤히는 검색창마다 광고가 아닌 **무해한 표식 문자열**(`hwonhi` + 임의 8자리)로 한 번 조회해,
표식이 결과 페이지에 그대로 나오는지와 색인 차단(`noindex`) 여부를 보고 등급을 매깁니다.

| 등급 | 조건 | 조치 |
|---|---|---|
| 취약 | 검색어가 페이지 **제목**에 나오고 색인 차단이 없음 | 검색결과 페이지에 `<meta name="robots" content="noindex">` 또는 `X-Robots-Tag: noindex` 헤더 추가 |
| 주의 | 본문에만 나오거나, `canonical` 만 있거나, `robots.txt` 로 수집만 막혀 있음 | 위와 같이 `noindex` 추가 권장 |
| (보고 안 함) | `noindex` 로 색인이 막혀 있거나 검색어를 반사하지 않음 | — |

`robots.txt` 차단은 검색엔진이 페이지를 **읽는 것만** 막고, 외부 링크가 많으면 주소 자체는
검색 결과에 뜰 수 있어 '주의'로 봅니다. 올바른 조치는 `noindex` 입니다.
POST 방식 검색창과 다른 사이트로 보내는 검색창(포털 검색 등)은 조회하지 않습니다.

**색인 목록**: 이미 **검색엔진에 노출된** 광고를 찾습니다. 반사형 광고 주소는 누리집 안
어디에도 링크되어 있지 않아 누리집을 돌아다니는 방식으로는 찾을 수 없고, 검색엔진 색인에만
있습니다. Google Search Console 에서 내려받은 페이지 목록(CSV)을 고급 설정의 **목록 파일 고르기** 로 넣으면 목록의 주소를 하나씩
열어 확인합니다. 버튼을 한 번 더 누르면 넣은 목록이 빠집니다.

| 등급 | 조건 | 조치 |
|---|---|---|
| 피해 발생 또는 광고 확인됨 | 주소에 담긴 광고 문구가 지금도 제목·본문에 나타남, 또는 페이지에 광고 문구가 있음 | Search Console 의 **삭제** 도구로 색인 삭제 요청, 검색결과 페이지에 `noindex` 추가 |
| 주의 (색인 잔존) | 광고 문구를 담은 주소가 색인되어 있으나 지금은 나타나지 않음 | 색인 삭제 요청 |
| 취약 | 광고는 없지만 누리집 탐색에서 못 본 검색 경로가 목록에 있고, 표식 조회로 반사가 확인됨 | 검색결과 페이지에 `noindex` 추가 |

- 점검 대상과 다른 도메인의 주소는 건너뜁니다. 한 번에 최대 1,000개를 확인합니다.
- 주소 열은 열 이름이 아니라 값을 보고 찾으므로 내보내기 종류나 화면 언어와 관계없이 읽습니다.
  엑셀에서 다시 저장한 파일(CP949)과 주소만 한 줄에 하나씩 적은 텍스트 파일도 됩니다.
- 목록에는 **피해 발생 또는 광고 확인됨** 건이 맨 위에 나옵니다.

**Search Console 에서 목록 내려받기** (누리집 소유 확인이 된 계정 필요, 메뉴 이름은 바뀔 수 있음)

1. Search Console 에서 점검할 누리집(속성)을 고릅니다.
2. **실적** → 아래쪽 **페이지** 탭을 엽니다. 기간은 넓게(예: 최근 16개월) 잡습니다.
3. 오른쪽 위 **내보내기** → **CSV 다운로드** 를 누릅니다.
4. 받은 파일(압축이면 풀어서 `페이지.csv`)을 훤히 고급 설정의 **목록 파일 고르기** 로 고릅니다.

**색인 생성 → 페이지** 화면의 목록을 내보낸 파일도 같은 방법으로 넣을 수 있습니다.

### 검색엔진 추가 탐색 (선택 기능)

누리집 안을 훑는 점검으로는 닿지 않는 **구글 검색 결과에 노출된 광고 주소**를 찾습니다. 검색창에 광고 문구를 넣어 만든
결과 주소, 지웠는데 검색에 남은 글이 대표적입니다. SerpApi 키가 필요하며(첫 장 '상용 AI API 사용 여부'), 키가 없어도
기본 점검은 그대로 동작합니다.

1. 점검이 끝난 결과 화면의 **검색엔진에 노출된 광고도 찾아보시겠습니까? → 추가 탐색하기** 를 누릅니다.
   시작 화면에는 나오지 않습니다.
2. **대상 도메인** 은 점검 주소로 채워집니다. 바꿨다면 **점검 주소로 되돌리기** 로 되돌립니다.
3. **검색할 광고 유형** 을 고릅니다. 공공 누리집에 실제로 노출된 광고에서 자주 보인 단어를 유형별로 정해 두었습니다
   (도박·사행성, 도박 주소·계좌 거래, 대포통장·불법 대출, 마약·불법 의약품, 성인·유흥, 고수익 알바·가담자 모집,
   외국어 도박 스팸 — 7개 분류 25개 단어). **이번 점검에서 찾은 단어** 도 골라 함께 검색할 수 있고,
   **고급: 검색 단어 직접 입력** 에 한 줄에 하나씩 더할 수 있습니다. 합쳐서 중복 없이 최대 30개입니다.
4. 바꿀 것이 있으면 **상세 설정**(처음에는 접혀 있습니다)을 엽니다. **검색 범위**, **키워드당 최대 페이지**(기본 2),
   **수집한 주소에 접속해 지금도 광고가 있는지 확인**, **구글 생략 필터 해제**(비교용)가 들어 있고, 바꾸지 않아도 됩니다.
   - **등록 도메인 전체(하위 도메인 포함)**(기본): `www.example.go.kr` 을 넣었으면 `example.go.kr` 과 그 하위 주소 전체를 검색합니다.
   - **입력한 주소만**: 입력한 호스트만 검색합니다. 이때만 **입력한 주소 아래의 하위 도메인도 포함** 칸이 나타나며, 켜면 그 아래 주소까지 결과에 넣습니다.
5. 화면에 `검색 단어 N개 · 구글 · 최대 M회 검색` 이 나옵니다. M회가 계정 호출량에서 차감될 수 있는 최대치입니다.
6. **보조 탐색 시작** 을 누릅니다. 진행 막대와 지금 검색 중인 단어·페이지, **단어별 검색 상태**(상태·수집 URL 수)가 보이고,
   API 오류·시간 초과처럼 결과를 받지 못한 질의는 **확인이 필요한 질의** 표에 사유와 함께 따로 나옵니다.
   이 질의들은 "광고 없음"이 아니라 확인하지 못한 것입니다. **검색 중지**(검색 중에만 나타납니다)로 멈추면 그때까지의 결과를 보존합니다.
   제공자 쪽에서 아직 끝나지 않은 검색은 **대기 결과 회수**(받을 결과가 있을 때만 나타납니다)로 다시 받아옵니다.
7. 끝나면 **검색 보고서 열기** 로 보고서를 엽니다. 점검 결과 보고서와 같은 양식(인쇄·PDF 저장, 결재란)이며
   수집한 URL마다 검색 당시 제목·요약 근거와 **광고 판정** 또는 **검토 필요** 가 붙습니다.

- 기본은 검색 결과만 모으고 누리집에는 접속하지 않습니다. **수집한 주소에 접속해 지금도 광고가 있는지 확인** 을 켜면 수집한 주소를 열어
  현재도 광고가 있는지(또는 삭제됐는지) 기본 점검과 같은 판정으로 확인합니다.
- 검색 결과의 제목·요약을 기본 점검과 같은 판정 사전으로 판정하며, 주소에 단어가 들어 있다는 이유만으로는 광고로 보지 않습니다.
- 광고로 판정한 항목은 `search_results/<실행폴더>/result_extra.json` 에 저장되고, 같은 대상이면 구동 파일 옆
  `result_extra.json` 에도 합쳐집니다(유형은 5장 `SEARCH_*_AD`). 기존 추가 탐지 결과는 지우지 않습니다.
- **지난 검색 보기** 에서 이 컴퓨터에 저장된 지난 검색을 다시 열어 보고서와 제출 반영 건수를 볼 수 있습니다.
- 점검·조치 확인·검색은 동시에 실행하지 않습니다. 자세한 동작은 `docs/검색엔진_보조탐색_사용법.md` 에 있습니다.

### 점검 키워드 화면

광고 여부를 가르는 키워드 목록을 화면에서 관리합니다. 바꾼 내용은 `keyword_state.json` 에 저장되어
**다음 점검부터** 화면 모드와 터미널 실행 모두에 적용됩니다. 점검 중에는 바꿀 수 없습니다.

오른쪽 위 **점검 키워드** 버튼을 누르면 같은 창 안에서 **점검 키워드 관리** 화면으로 이동합니다. 단계 표시 자리에
돌아가기 단추(예: **← 점검 결과로**)가 나오며, 누르면 들어오기 전 화면으로 돌아갑니다. 이 화면을 보는 동안 점검이 끝나면
화면을 바꾸지 않고 돌아가기 단추만 **← 점검 결과로** 로 바뀝니다. 왼쪽은 단어 추가 줄과 분류별 키워드 목록, 오른쪽은
시험해 보기이며, 창 폭이 좁으면 시험해 보기가 목록 아래로 내려갑니다.

| 기능 | 사용법 |
|---|---|
| 목록 보기 | 분류마다 상자 하나로 보입니다. 분류는 불법 은어 키워드·유해 업종·종목 키워드·불법 행위·품목 키워드·광고 유도 키워드·오탐 방지 키워드이며, 이름 옆에 판정 세기(이것만으로 광고·단서 1개 더 등)가 붙습니다. 단어가 많은 분류는 **펼치기** 로 전체를 봅니다 |
| 목록에서 찾기 | 단어 추가 줄 오른쪽 칸에 넣으면 모든 분류에서 그 글자가 든 단어만 보입니다 |
| 기본 단어 끄기 | 기본 단어를 누르면 꺼지고(취소선·'꺼짐'), 다시 누르면 켜집니다. 아래쪽 알림의 **되돌리기** 로 바로 취소할 수 있습니다 |
| 추가한 단어 지우기 | 빨간 단어(직접 추가한 것)를 누르고 확인하면 지워집니다 |
| 기본값으로 되돌리기 | 추가한 단어를 모두 지우고 꺼 둔 기본 단어를 모두 켭니다 |
| 단어 추가 | 분류를 고르고 단어를 넣은 뒤 **추가** 를 누릅니다. 추가한 단어는 그 분류 맨 앞에 빨간색으로 나타납니다. 띄어쓰기는 무시되며, 두 글자 이상이어야 하고 이미 있는 단어는 추가할 수 없습니다 |
| 시험해 보기 | 문장을 넣고 **판정 보기**(또는 Enter)를 누르면 숨겨진 글일 때와 화면에 그대로 보이는 글일 때의 판정과 판정 등급(확실·의심·경계), 찾은 단어와 그 분류, 오탐 방지 키워드, 위장 글자를 복원한 글이 나옵니다. 찾은 단어는 왼쪽 목록에 노랗게 표시되고, 단어를 바꾸면 판정이 바로 다시 계산됩니다 |

분류마다 판정 방식이 다르므로(5장 '광고 판정 범위'), 단어를 추가하기 전에 시험해 보기로 정상 공지가 광고로 잡히지 않는지
확인하십시오. 특히 정상 글에도 흔한 말을 **불법 은어 키워드** 에 넣으면 오탐이 크게 늘어납니다. `keyword_state.json` 이 없거나
손상되었으면 내장 기본 사전으로 동작합니다.

### 증거 보기 탭

숨김 처리를 일시적으로 해제하고 촬영한 화면입니다. 실제 누리집에서는 보이지 않는 내용이므로,
조치 요청이나 보고 자료의 근거로 사용할 수 있습니다.

### 누리집 보기 탭

점검 시점의 페이지를 그대로 다시 열어 검출 위치를 붉게 표시합니다. 저장본이므로 링크는
동작하지 않을 수 있습니다.

### 원본 소스 탭

검출된 요소의 원본 HTML 입니다. 게시물 수정 화면에서 해당 부분을 찾아 삭제할 때 사용합니다.

### 종료

화면 오른쪽 위 **프로그램 종료** 버튼을 누르거나 창을 닫습니다. 창을 닫으면 약 3초 안에 프로그램이 끝나며,
점검 중이었다면 점검도 멈춥니다. 새로고침은 종료로 보지 않습니다. 종료 신호 없이 화면이 사라진 경우(브라우저 강제 종료 등)에는
약 30초 뒤 스스로 정리됩니다.

## 4. 실행 옵션

| 옵션 | 설명 | 기본값 |
|---|---|---|
| `--url <주소>` | 점검 대상 진입 URL | 없음(화면 모드) |
| `--cli` | 화면 없이 터미널로만 실행 (자동화용) | 꺼짐 |
| `--out <폴더>` | 결과 파일 생성 폴더 | 구동 파일 폴더 |
| `--max-pages <수>` | 최대 점검 페이지 수 | 5000 |
| `--time-limit <분>` | 이 시간이 지나면 새 페이지를 열지 않고 지금까지의 결과로 마침 (0 이면 제한 없음) | 25 |
| `--polite` | 요청 간격을 두고 `robots.txt` 를 지킴 | 꺼짐 |
| `--delay <초>` | 페이지 사이 간격 | 0.7 |
| `--ignore-robots` | `robots.txt` 무시 | 꺼짐 |
| `--cloaking` | 검색엔진 크롤러 신원으로 한 번 더 조회해 위장 여부 확인 | 꺼짐 |
| `--subdomains` | 같은 기관 도메인의 서브도메인·다른 포트 주소도 따라가 점검 | 꺼짐 |
| `--check-links` | 바깥 링크의 목적지를 도메인마다 한 번 조회해 광고 사이트로 바뀌지 않았는지 확인 | 꺼짐 |
| `--ocr-images` | 본문 그림을 받아 Windows 글자 인식으로 읽고 그림으로 올린 광고 문구를 찾음 | 꺼짐 |
| `--evidence` | 증거 화면을 함께 저장 | CLI·화면 모드 모두 꺼짐 |
| `--attachments` | 첨부파일(PDF·HWP·HWPX·DOCX·XLSX·PPTX·zip) 안의 광고도 검사 | CLI·화면 모드 모두 꺼짐 |
| `--search-reflect` | 검색창이 검색결과 반사형 광고에 악용될 수 있는지 점검 | CLI·화면 모드 모두 꺼짐 |
| `--index-csv <파일>` | Search Console 에서 내려받은 색인 페이지 목록(CSV)의 주소를 하나씩 열어 광고 노출 확인 | 없음 |
| `--port <번호>` | 화면 모드 포트 | 8900 |
| `--quiet` | 진행 상황 출력 생략 | 꺼짐 |

## 5. 점검 유형

### 주요 유형 (`result.json`)

| 코드 | 이름 | 예시 |
|---|---|---|
| `HOMOGLYPH` | 닮은꼴 글자 위장 | `ｍｅｇａ－ＢＥＴ`, `роуаl casino` |
| `JAMO` | 자모 분해 | `ㅋㅏㅈㅣㄴㅗ ㅂㅗㄴㅓㅅㅡ` |
| `TRANSPARENT` | 투명 텍스트 | `opacity:0`, `color:transparent`, 배경색과 동일 |
| `OFFSCREEN` | 화면 밖 은닉 | `display:none`, `font-size:0`, `left:-9999px` |

한 요소에 두 기법이 겹쳐 있으면 기법별로 각각 한 건씩 보고합니다.

### 광고 판정 범위

숨겨진 글이라도 광고가 아니면 보고하지 않습니다. 광고 여부는 표현 사전과 유인 신호의 가중치로 판정합니다.

| 분야 | 판정 방식 |
|---|---|
| 불법 은어 키워드 (도박·성인물) | 도박·성매매·음란물 광고에서만 쓰는 은어(먹튀·안전놀이터·첫충·토토사이트·조건만남·성인라방·섹파 등)는 이것만으로 광고로 봅니다 |
| 유해 업종·종목 키워드 (도박 종목·성인 방송·성매매 업소) | 카지노·토토·바카라, 음란·벗방·몸캠, 휴게텔·키스방·룸싸롱 등은 단속 보도·도서 소개·예방 공지에도 나오므로 **다른 단서가 하나 더 있어야** 광고로 봅니다. 화면에 그대로 보이는 글은 연락처나 외부 주소가 있어야 합니다 |
| 불법 행위·품목 키워드: 마약, 대포통장·돈세탁, 대포폰·대포유심, 불법 대출, 불법 고수익 알바, 라방, 발기부전 치료제 판매, 흥신소·심부름센터, 소액결제·신용카드 현금화, 신분증 위조, 검색 순위 조작(백링크) | 예방 교육·피해 주의 안내에도 쓰이는 말이라, 판매·연락처·금액 같은 **유인 신호가 함께 있을 때만** 광고로 봅니다. 신고·처벌·예방·주의 같은 오탐 방지 키워드가 있으면 점수를 낮춥니다 |

출장마사지·출장샵처럼 출장 성매매 광고에서만 쓰는 말은 불법 은어 키워드로 봅니다.

광고 유도 키워드(회원가입·상담·이벤트·모집·문의 등)만 여럿 겹친 글은 연락처·외부 주소·문자 위장 같은 유인 신호가 함께 있을 때만
광고로 봅니다. 숨겨 둔 모바일 메뉴·탭·팝업은 이런 말이 길게 이어져 있어 광고로 잘못 볼 수 있기 때문입니다.
`www.gov.kr` 처럼 공공기관 주소(`go.kr`·`korea.kr`·`ac.kr` 등)는 외부 주소 신호로 세지 않습니다.

닮은꼴 글자 위장은 위장 글자가 다른 라틴 글자와 이어져 하나의 낱말로 읽힐 때만 인정합니다(`ｃａｓｉｎｏ`, `саsinо`,
`텔 🅞🅝❹❾❽❾`). 날짜의 `～`, `（주）`, 단위 `㎏`·`μg`·`mℓ`, `℡`·`№`·`™`, 목록 번호 `ⓐ`·`❶` 처럼 홀로 쓰인 전각·특수 기호는
공공 문서에 흔하므로 위장으로 보지 않습니다. 전각 숫자는 글자와 섞였거나 전화번호처럼 7자 이상 이어질 때만 위장으로 봅니다.

배경이 그림(`background-image`)인 글자는 바탕색을 알 수 없으므로 '배경과 같은 색' 기준으로는 투명 텍스트로 보지 않습니다
(어두운 배너 그림 위 흰 글씨를 숨긴 글로 잘못 보지 않기 위함). `opacity:0`·`color:transparent` 는 그대로 판정합니다.
배경이 그라데이션이면 그 안의 모든 색과 구분되지 않을 때만 투명 텍스트로 봅니다.

연락처(텔레그램 `@아이디`, `t.me/`, '텔레·탤레' 같은 표기 변형, 카카오톡, 휴대전화 번호), 외부 주소, 금액·비율은 유인 신호로 셉니다.
키워드 목록은 **점검 키워드** 화면에서 추가하거나 끌 수 있습니다(3장).

## 6. 점검 대상 보호

본 도구는 **조회(GET)만 수행**합니다. 게시물 작성과 폼 전송(POST)은 하지 않습니다.
예외는 '댓글 더보기' 단추가 댓글 목록을 비동기 POST 로 불러오는 경우 하나입니다(아래 참고).
값을 넣는 동작은 검색창 점검 하나뿐이며, 광고가 아닌 무해한 표식 문자열로 **검색 기능마다
한 번** 조회합니다. 모든 페이지 머리에 있는 통합검색처럼 같은 검색 기능은 다시 조회하지 않습니다.

게시판 목록이 `javascript:fn_view('1024')`, 행 클릭(`onclick`), 스크립트 클릭 이벤트, 숨은 폼으로 넘기는
페이지 번호처럼 **자바스크립트로만 이어지는 경우**에는 해당 요소를 눌러 갈 곳의 주소만 알아냅니다.
이때 페이지 이동은 브라우저 안에서 취소되고, GET 이 아닌 요청(삭제·등록 등)은 모두 차단되며,
삭제·수정·로그아웃·추천·신고처럼 이름이 위험해 보이는 요소는 누르지 않습니다. 확인 창은 '취소'로 닫습니다.
`fn_link_page(2)` 처럼 숨은 폼을 POST 로 보내 여는 목록·게시글은 POST 를 보내지 않고, 보내려던 값을
같은 주소의 GET 요청으로 바꿔 **한 번** 열어 봅니다(전자정부 표준프레임워크 게시판 대부분이 GET 으로도 받습니다).
주소가 삭제·등록·수정·저장·처리(`delete`·`insert`·`update`·`save`·`proc` 등)처럼 보이면 바꾸지 않고,
GET 을 받지 않아 오류가 돌아오면 그 주소는 건너뜁니다.

화면을 내려야 불러오는 댓글(지연 불러오기)은 페이지를 끝까지 내려 불러온 뒤 판정합니다. 페이지가 그런 장치를 쓸 때만
내려 보므로 다른 페이지의 점검 시간은 늘지 않습니다. '댓글 더보기'·'이전 댓글' 같은 단추는 최대 세 번까지 눌러 같은 페이지에
글을 더 불러옵니다. 이때도 페이지 이동은 취소합니다. 전자정부 게시판은 댓글 목록을 비동기 POST(`selectCmtList.do` 등)로
불러오는 경우가 많아, **주소에 조회 낱말(list·select·get·search·more·load·view 등)이 있고 쓰기 낱말(delete·insert·update·
write·save·regist·proc·vote·report·Del 등)이 없는 비동기 POST 만** 보냅니다. 그 밖의 POST, 폼 전송, 페이지 이동은 모두 막습니다.
자바스크립트 링크를 눌러 갈 곳을 알아낼 때(위)는 이 예외 없이 POST 를 전혀 보내지 않습니다.
실제 주소로 이동하는 '더보기' 링크는 누르지 않고 크롤링으로 따라갑니다.

첨부파일 검사는 파일 하나에 10초, 점검 한 번에 모두 합쳐 3분까지만 씁니다. 첨부가 아주 많은 누리집에서 나머지 파일은
검사하지 않습니다.

같은 URL은 한 번만 봅니다. 옛 주소·짧은 주소가 다른 주소로 넘겨지면(리다이렉트) 넘겨진 주소를 실제 페이지로 보고,
이미 본 주소이면 다시 보지 않습니다. 결과 파일에도 넘겨진 주소로 적습니다. 쿼리 항목의 순서·끝 슬래시·http/https·`#` 뒤의 조각만 다른 주소는
같은 페이지로 봅니다. 쿼리 값(빈 값 포함), 세션 주소(`;jsessionid=`), 유입 추적 파라미터(`utm_…` 등), 경로 대소문자는
실제 본문을 바꿀 수 있어 보존합니다. 내용이 같더라도 이런 값이 다른 URL의 검출은 각각 보고합니다(모집요강 12쪽 URL 비교 규칙).
frameset·iframe 으로 짠 누리집은 프레임 안의 링크도 따라갑니다.
달력·정렬·검색 조건(`year`·`month`·`date`·`sort`·`order`·`search…`·`keyword` 등)에 값이 붙은 주소는 값만 바꿔 끝없이
만들어지므로, 다른 주소를 모두 본 뒤 남은 페이지 수로만 봅니다. 점검용 브라우저 탭이 도중에 죽으면 새 탭을 열어 이어 갑니다.

실제 기관 누리집을 점검할 때는 화면의 **천천히 점검**(터미널은 `--polite`)을 켜십시오. 요청 사이에 간격을 두고
`robots.txt` 의 `Disallow` 경로를 건너뜁니다. User-Agent 에 도구 이름을 밝히므로 서버 로그를
확인하는 담당자가 정상 점검임을 알 수 있습니다.

검색엔진 추가 탐색은 SerpApi 에만 질의하고 점검 대상 누리집에는 접속하지 않습니다. **수집 후 대상 URL 재검사** 를
켰을 때만 수집한 주소를 하나씩 열며, 이때도 위와 같이 조회만 하고 `robots.txt`·요청 간격을 지킵니다.

**권한이 있는 누리집에만 사용하십시오.**

## 7. 실행이 차단되는 경우

Windows 11 의 **Smart App Control** 이 켜져 있으면 서명되지 않은 프로그램을 평판이 없다는
이유로 차단할 수 있습니다. 이 경우 "애플리케이션 제어 정책에서 이 프로그램을 차단했습니다"
라는 메시지가 나타납니다.

| 확인 | 방법 |
|---|---|
| 설정 상태 | Windows 보안 → 앱 및 브라우저 제어 → 스마트 앱 제어 |
| 해제 | 같은 화면에서 끄기 (한 번 끄면 다시 켤 수 없습니다) |

본 도구는 조회만 수행하며 외부로 자료를 보내지 않습니다. 배포 시 코드 서명 인증서를 적용하면
이 차단은 발생하지 않습니다.

### "Windows에서 PC를 보호했습니다" 창이 뜨는 경우

메일이나 인터넷으로 받은 프로그램을 처음 실행하면 Microsoft Defender SmartScreen 이 이 창을
띄울 수 있습니다. 차단이 아니라 확인 절차입니다.

1. 창 안의 **추가 정보** 를 누릅니다.
2. 아래에 나타나는 **실행** 을 누릅니다.

한 번 실행하면 같은 파일로는 다시 묻지 않습니다.

## 8. 자주 묻는 상황

| 상황 | 확인 사항 |
|---|---|
| 검출이 0건이다 | 진입 URL이 게시판 목록인지, `--max-pages` 가 충분한지 확인 |
| 일부 페이지를 건너뛴다 | 천천히 점검(`--polite`)을 켜면 `robots.txt` 가 막고 있을 수 있음 |
| 시간이 오래 걸린다 | 최대 페이지(`--max-pages`)를 줄이거나, 시험용이면 천천히 점검(`--polite`)을 끄십시오. 25분이 지나면 스스로 멈추고 그때까지의 결과를 저장합니다 |
| '중지함'·'시간 초과로 중단'이 붙는다 | 점검 중지를 눌렀거나 25분 상한에 닿은 경우입니다. 게시판 주소를 따로 넣어 나눠 점검하십시오 |
| '페이지 한도 도달'이 붙는다 | 최대 페이지 수까지 점검하고 남은 주소가 있습니다. 고급 설정에서 최대 페이지 수를 늘리거나 게시판 주소를 따로 넣으십시오 |
| '접속 막혀 중단'·'못 연 페이지 N건'이 붙는다 | 서버가 요청을 막았거나 응답하지 않은 경우입니다. '천천히 점검'을 켜고 다시 점검하십시오 |
| 댓글이 다 안 나온다 | '더보기'가 조회로 보이지 않는 주소(예: `/api/comments`)로 POST 를 보내면 안전을 위해 보내지 않습니다 |
| POST 로 여는 게시글의 주소 | 숨은 폼을 POST 로 보내 여는 글은 같은 값을 GET 주소(`view.do?nttId=…`)로 바꿔 열고, 결과에도 그 주소로 적습니다 |
| 증거 화면이 비어 있다 | 증거 사진과 원본 코드는 고급 설정의 ‘검출 증거 사진 저장’을 켜고 점검해야 저장됩니다. 켜고 점검했는데 비어 있다면 해당 요소가 촬영 시점에 사라진 경우입니다 |
