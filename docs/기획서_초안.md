## 2. 개발 기획 내용

### 2-1. 개발 제안 배경 및 목적

**문제 인식**

2025년 11월 언론 조사에서 `go.kr` 도메인 61개 사이트에 불법광고 1,169건이 게시·은닉된 사실이
확인되었다. 보건복지부 345건, 나주시 320건, 인천시 103건 등 중앙부처와 지방자치단체를 가리지
않았으며, 마약 거래와 대포통장 매입을 안내하는 문구까지 포함되어 있었다.

주목할 점은 대부분이 서버 침해의 결과가 아니라는 것이다. 게시판 검색창에 광고 문구를 입력해
생성된 검색결과 URL을 외부에서 대량 링크해 검색엔진이 수집하도록 유도하거나, 정상 게시물 안에
사람 눈에 보이지 않는 형태로 문자열을 심는 방식이 주로 쓰였다. 서버에 흔적이 남지 않으므로
관리자가 게시판을 아무리 확인해도 발견되지 않는다. 실제로 해당 기관들은 "사실을 인지하지
못했다"고 답했다.

**현행 체계의 공백**

기관 누리집은 운영·유지관리 용역을 통해 관리되지만, 해당 과업지시서에는 홈페이지 변조 방지
모니터링과 웹 취약점 진단은 포함되어도 불법광고 탐지는 과업 항목이 아니다. 국내 상용 스팸 차단
솔루션은 메일 스팸을 대상으로 하며, 기존 게시판 금칙어 필터는 자모 분해나 닮은꼴 문자 치환에
쉽게 우회된다. 즉 **은닉형 불법광고를 겨냥한 점검 수단이 제도적으로 비어 있다.**

**개발 목적**

본 도구는 점검 대상 누리집 주소를 입력하면 하위 페이지·게시글·댓글과 iframe 내부까지 훑어
게시되거나 숨겨진 불법광고를 자동으로 찾아내고, 담당자가 즉시 조치할 수 있는 형태로 결과를
제공하는 것을 목적으로 한다.

### 2-2. 개발 상세 설명

**설계 원리**

불법광고의 목적은 "사람 눈에는 보이지 않고 검색엔진에는 보이게" 만드는 것이다. 이 모순이 곧
탐지 지점이 된다. 본 도구는 세 가지 차이를 측정한다.

```
DOM에 있는 것  ≠  화면에 보이는 것      →  투명 텍스트 · 화면 밖 은닉 탐지
쓰여진 글자    ≠  의미하는 단어         →  닮은꼴 글자 위장 · 자모 분해 탐지
텍스트 노드    ≠  실제 노출되는 문자열  →  메타 태그 · 속성값 · 링크 탐지(추가 유형)
```

**처리 흐름**

```
URL 입력
  → 같은 도메인 크롤링 (하위 페이지·게시글·댓글, iframe 재귀 순회,
     javascript:·onclick·스크립트 이벤트로만 이어지는 게시판 링크, 비동기로 불러오는 댓글)
  → 브라우저 렌더링 후 계산된 스타일 수집
  → 은닉 판정 (무엇이 어떻게 감춰졌는가)
  → 문자 정규화 (자모 재결합·닮은꼴 복원·제로폭 제거·숫자 치환 복원)
  → 광고 판정 (가중치 사전)
  → 유일성이 검증된 CSS 선택자 생성
  → (추가) 첨부파일 본문 · 검색창 반사 점검 · 색인 목록 점검
  → result.json · result_extra.json / 화면 / 증거 이미지
```

**주요 탐지 유형 4종**

| 코드 | 판정 근거 |
|---|---|
| HOMOGLYPH | 전각·키릴·그리스·수학용 문자 등 NFKC가 ASCII 글자로 되돌리는 문자 혼용 |
| JAMO | 호환 자모·조합용 자모를 재결합했을 때 음절이 새로 생성되는 경우 |
| TRANSPARENT | `opacity`·`filter:opacity()`, `color:transparent`·`-webkit-text-fill-color`, 알파 합성 후 배경과의 대비비 |
| OFFSCREEN | `display:none`, `visibility`, `font-size≤1px`(transform 축소 반영), 화면 밖 좌표(오른쪽 포함), `text-indent`, `clip`·`clip-path` 잘린 넓이 0, 상위 요소 `overflow:hidden` 밖으로 밀린 글자, 접힌 상자 |

가상 요소(`::before`/`::after`) content와 Shadow DOM 내부, 중첩 iframe까지 대상에 포함한다.

**추가 탐지 유형**

| 유형 | 내용 |
|---|---|
| OCCLUDED | 다른 요소에 완전히 덮여 보이지 않는 광고 |
| META_SPAM | `title`, `description`, `keywords` 등 메타 태그 오염 |
| ATTR_SPAM | `alt`, `title`, `aria-label` 속성값에 숨긴 광고 |

| ATTACHMENT_AD | 게시글 첨부파일(PDF·HWP·HWPX) 본문에 넣은 광고. 첨부 링크를 내려받아 글자를 꺼내 같은 사전으로 판정. 주소에 확장자가 없는 내려받기(FileDown.do 등)도 파일 머리로 형식을 판별 |

| VISIBLE_AD | 숨기지 않고 게시판·방명록·댓글에 그대로 올린 광고 글 (실제 사례에서 가장 많은 유형) |

**검색결과 반사형 광고 대응**

문제 인식에서 밝힌 대로 실제 피해의 주된 수법은 검색창 악용이다. 검색창에 광고 문구를 넣어
만든 `검색결과 주소`를 외부에서 대량 링크하면, 검색엔진이 이를 기관 페이지로 색인해 도박 키워드
검색 결과에 기관 도메인이 광고 문구를 제목으로 달고 노출된다. 광고는 서버에 저장되지 않고
**주소와 검색엔진 색인에만** 존재하므로, 누리집을 돌며 숨은 문구를 찾는 방식으로는 원리상
닿을 수 없다. 본 도구는 이를 두 방향에서 다룬다.

```
[예방] 검색창 점검 (SEARCH_REFLECT) — 외부 의존 없음, 폐쇄망 동작
  탐색 중 발견한 GET 검색 폼마다 무해한 표식 문자열로 1회 조회
  → 표식이 <title>·본문에 반사되는가, noindex(메타·X-Robots-Tag)가 있는가,
    canonical·robots.txt 는 어떤가
  → 취약(제목 반사·차단 없음) / 주의(본문 반사·canonical·robots.txt 만) 등급과 조치 안내

[사후] 색인 목록 점검 (SEARCH_INDEXED) — 담당자가 Search Console 목록을 넣을 때
  색인된 주소를 하나씩 조회 → 주소에 담긴 광고 문구가 지금도 제목·본문에 뜨면 '피해 확인'
  목록에서 처음 알게 된 숨은 검색 경로는 [예방] 점검으로 넘겨 반사 여부 확인
```

`robots.txt` 로 검색 경로를 막는 것은 흔한 대응이지만 검색엔진이 페이지를 **읽는 것만** 막을 뿐
외부 링크로 알려진 주소의 색인은 막지 못한다. 본 도구는 이를 '주의'로 분류하고 `noindex` 적용을
안내한다. 색인 목록은 기관 담당자가 자기 누리집 권한으로 내려받는 파일이므로 검색 API 키나
비용이 들지 않는다.

**오탐 억제**

은닉 기법이 쓰였다는 사실만으로는 위반이 아니다. 스킵 내비게이션이나 스크린리더용 요약문도
화면에서 감춰지기 때문이다. 따라서 **"감춰졌는가"와 "광고인가"를 분리해 판정**하고, 후자는
확정 표현·보조 표현·유인 신호(연락처·외부주소·금액)에 가중치를 두어 임계값으로 결정한다.

**AI 적용 여부**

적격평가는 `url`·`location`·`technique` 일치로 채점되며 `evidence_text`는 채점에 쓰이지 않는다.
따라서 규칙 기반으로 처리 가능한 영역에 생성형 모델을 투입하면 검출 시간과 운영 비용만 증가한다.
본 도구는 **AI API를 사용하지 않으며**, 외부 호출이 없으므로 토큰 비용과 망 제약이 발생하지 않는다.

noindex 검색창·POST 검색창·검색이 아닌 폼·정상 색인 주소는 보고하지 않았다.

**화면 구성**

| 탭 | 기능 |
|---|---|
| 탐지 결과 | 기법별 필터·검색, 조치 상태(미조치·조치완료·오탐)와 담당자 메모, CSV 내려받기 |
| 증거 보기 | 은닉 스타일을 일시 해제해 촬영한 화면 — 조치 근거 자료로 사용 |
| 누리집 보기 | 탐지 시점 페이지를 다시 열어 검출 위치를 직접 표시 |
| 원본 소스 | 검출 요소의 원본 HTML |

조치 상태는 `url+location+technique` 기준으로 보관되어 **재탐지해도 이력이 유지**된다.

**점검 대상 보호**

배포 후 담당자가 자기 기관 서버에 돌리는 도구이므로, 요청 간격 제한, `robots.txt` 준수,
정체를 밝히는 User-Agent, 조회 전용(GET) 동작을 갖추었다. 폼 전송(POST)은 수행하지 않으며,
값을 넣는 동작은 검색창 점검에서 무해한 표식 문자열로 검색 기능마다 한 번 조회하는 것뿐이다.
자바스크립트로만 이어지는 게시판 링크는 눌러서 목적지 주소만 얻되, 이동은 브라우저 안에서 취소하고
GET 이 아닌 요청은 차단하며 삭제·수정·로그아웃 등 위험해 보이는 요소는 누르지 않는다.

**배포 형태**

Windows 11에서 별도 설치 없이 실행된다. 탐지 엔진으로 Windows에 기본 탑재된 Microsoft Edge를
사용하므로 브라우저를 따로 내려받지 않으며, 폐쇄망에서도 동작한다.

### 2-3. 활용방안 및 기대효과

**활용 방안**

1. 각급 기관 담당자가 정기 점검 도구로 사용 — 별도 설치·계정·비용 없이 실행
2. 누리집 운영·유지관리 용역의 과업 항목으로 편입해 정기 점검을 제도화
3. 탐지 결과(CSV)를 상급기관 취합 양식으로 활용해 기관별 현황 파악
4. 공공 웹사이트 품질관리 체계와 연계

**기대효과**

| 구분 | 내용 |
|---|---|
| 국민 편익 | 민원·교육 정보를 찾는 국민이 공공 누리집에서 도박·성인물 광고에 노출되는 일을 줄인다 |
| 행정 효율 | 수작업으로는 발견이 불가능한 은닉형 광고를 자동 탐지하고, 조치 위치와 방법을 함께 제시해 처리 시간을 단축한다 |
| 신뢰 보호 | 공공 도메인의 검색 신뢰도를 빌려 불법 사이트가 상위 노출되는 구조를 차단한다 |
| 확산성 | 설치가 필요 없고 외부 비용이 들지 않아 소규모 기관까지 동일하게 배포 가능하다 |
