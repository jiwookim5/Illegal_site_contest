# 점검 상태 저장 및 이어서 점검

## 변경 전 보존

`codex/resumable-scans` 브랜치의 `fb577fa`에 기존 정상 문맥 감점·검토 후보·시험 자료 작업을 먼저 커밋했다. 기존에는 결과 복구만 가능했고 실제 탐색 재개 기능은 없었다.

## 사용자 흐름

- 시작할 때 회차별 시간 25·50·120분을 선택한다. 페이지 한도도 회차마다 적용한다.
- 시간 초과·사용자 중단·페이지 한도 도달 후 남은 작업이 있으면 결과 화면에 **이어서 점검**, 시간 선택, **저장하고 종료**가 나타난다. 결과는 이미 저장되어 있다.
- 앱 재시작 후 지난 기록의 **이어서 점검**을 눌러 같은 설정으로 진행한다.
- 완료 페이지는 건너뛰고 중단된 페이지는 다시 연다. 결과는 이전 회차와 합쳐 동일 URL·위치·유형의 중복을 제거한다.
- 같은 점검 식별자와 이전 회차 식별자를 기록하고, 회차 수·누적 시간을 표시한다. 새 회차는 별도 보관 폴더를 가지므로 이전 증거를 덮어쓰지 않는다.

## 저장 범위

버전이 있는 JSON 상태에 전체 대기열(본문 우선 순서 포함), 후순위 주소, 재시도 대기열, 방문·완료 주소, 재시도 횟수에 해당하는 상태, 반복 탐색 제한, 로그인 우회 기록, 범위, 본문 지문, 결과와 증거 참조를 저장한다. 화면의 미방문 주소 표시는 200건까지만 보여 주지만 재개 데이터는 잘리지 않는다.

페이지를 열기 전과 완료 시점, 파일·이미지 검사 완료, 연계 링크 검사 완료 시 상태를 저장한다. 강제 종료 시에는 마지막 원자적 저장 파일을 읽으며 진행 중이던 페이지는 완료 처리하지 않는다. 중단된 페이지의 링크 수집·검색 점검 상태는 재실행할 수 있도록 되돌린다.

첨부파일·이미지는 완료 캐시를 보존하고, 예산 때문에 미처리한 항목을 실패 캐시에 넣지 않는다. 이런 항목이 있는 페이지는 미완료로 남겨 다음 회차에 다시 분석한다. 연계 링크는 목적지별 완료 상태와 결과를, 색인 목록은 주소별 완료 상태를 보존한다. 첨부·이미지 페이지를 재분석할 때는 해당 페이지의 현재 내용을 읽는다. 사이트 내용이 바뀌었을 때 과거 DOM을 복원하여 검사하는 기능은 아니다.

## 재개 조건과 한계

- 당시 저장한 키워드 사전과 점검 설정을 사용한다. 현재 사용자가 바꾼 사전을 과거 결과에 섞지 않는다.
- 탐지 코드/실행 파일 지문이 바뀌면 재개를 거절하고 새 점검을 안내한다.
- 봉인된 기록의 파일 해시와 사전 해시를 확인하고, 손상된 기록은 재개하지 않는다.
- 기존의 실패 재시도·반복 탐색 제한은 이어받는다. 이미 재시도 한도를 소진한 실패 주소를 무한 반복하지 않는다.
- 구버전 결과에는 전체 대기열이 없으므로 소급하여 재개할 수 없다.
- 로그인 세션·브라우저 쿠키를 복원하는 기능은 아니다. 공개 누리집의 새 브라우저 세션으로 재개한다.
- 실행 중 시간 연장, CLI 전용 재개 명령은 추가하지 않았다. CLI에서 새로 만든 저장 기록도 앱의 지난 기록에서 재개할 수 있다.
- 실행 파일 재빌드·배포는 하지 않았다. 소스 실행에 적용되는 변경이다.

## 검증

실제 기관 누리집은 탐지하지 않고 localhost 시험 서버만 사용했다. 새 재개 시험은 전체 대기열 251개 보존, 완료 페이지 건너뛰기, 중단 페이지 재분석, 시간 종료, 강제 워커 종료, 추가 검사 캐시, 앱 재시작 및 화면의 50분 재개 선택, 이전 증거·사전·회차 보존을 확인한다.

검증 결과:

- 새 재개 시험 10개 통과. 첨부파일 완료 캐시 재사용과 색인 검사 순서 유지도 포함한다.
- 940px 화면에서 재개 버튼·시간 선택·저장 후 종료 표시와 50분 설정 전달 확인. 화면 오류 0건. `_regress/resume-controls.png`에 화면을 보존했다.
- 기존 저장 검사 26개, 결과 UI 검사 10개, 요청 안전 검사 2개, 엔진 이슈 검사 9개, 탐지 회귀 검사 11개, 실행 계약 검사 8개 통과. UI 이력·중지 컨트롤·키워드 화면 검사도 통과했다.
- 실제 예문 광고 73건·정상 69건의 기대 판정 불일치 0건. 기존 별도 미탐 목록 3건은 그대로다.
- 전체 18개 시험 구성에서 주요 정답 101/101 검출. 직전 정상 문맥 작업의 최종 집계와 주요·추가 결과 집합을 비교해 변화 0건이다. OCR 시험 사이트도 실행되었으며, 이는 모든 OCR 환경에서의 정확도를 보장하는 결과는 아니다.
- 전체 회귀 명령의 종료 코드는 1이다. 오래된 `baseline.json`과 기존 선택자 표기·URL 구분 차이가 남아 있기 때문이며, 기준 파일을 덮어쓰지 않았다. 색인 점검의 최종 보완 뒤 `testsite6`을 별도 재실행해 종료 코드 0, 추가 결과 8건 유지도 확인했다.
