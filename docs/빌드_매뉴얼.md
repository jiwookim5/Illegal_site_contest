# 훤히 — 공공 누리집 숨은 불법광고 탐지 도구 — 실행·빌드 매뉴얼

제출한 구동 파일을 소스에서 동일하게 재현하기 위한 문서입니다.

## 1. 개발 환경

| 항목 | 버전 |
|---|---|
| 운영체제 | Windows 11 (빌드는 반드시 Windows 에서 수행) |
| Python | 3.12 이상 |
| PyInstaller | 6.x |

PyInstaller 는 크로스 컴파일을 지원하지 않습니다. Windows 용 실행 파일은 Windows 에서만
만들 수 있습니다.

## 2. 의존성

기본 외부 패키지는 아래와 같습니다. 정확한 버전과 전이 의존성은 `requirements.in`·`requirements.lock`을 따릅니다. OCR·EXE 빌드 선택 의존성은 별도입니다.

```
playwright        1.63.0   브라우저 제어
  greenlet        (playwright 의존)
  pyee            (playwright 의존)
pypdf             6.19.0   첨부 PDF 글자 추출 (BSD)
olefile           0.47     첨부 HWP(한글 5.0) 읽기 (BSD)
pypdfium2         5.6.0    PDF 렌더링
fonttools[woff]   4.66.1   웹 글꼴 윤곽 비교 (Brotli·Zopfli 포함)
```

HWPX 는 zip + XML 이므로 표준 라이브러리로 읽습니다.

화면(UI)은 표준 라이브러리 `http.server` 로 제공하므로 웹 프레임워크가 필요 없습니다.

## 4. 환경 준비

```powershell
cd <프로젝트 폴더>
python -m venv .venv
.venv\Scripts\python -m pip install --upgrade pip
.venv\Scripts\python -m pip install --require-hashes -r requirements.lock
.venv\Scripts\python -m pip install pyinstaller
.venv\Scripts\python -m pip install winrt-runtime winrt-Windows.Media.Ocr winrt-Windows.Graphics.Imaging winrt-Windows.Storage.Streams winrt-Windows.Globalization winrt-Windows.Foundation winrt-Windows.Foundation.Collections
```

`winrt-*` 는 그림 속 글자 인식(Windows 내장 `Windows.Media.Ocr`)을 파이썬에서 부르는 데 씁니다. 설치하지 않아도
탐지는 동작하고, 그림 속 글자 검사만 '할 수 없음' 으로 건너뜁니다. `pypdfium2`(PDFium, Apache-2.0·BSD)는 글자층 없는 스캔 PDF 페이지를
그림으로 그려 글자 인식에 넘기는 데 씁니다(없으면 PDF 안의 JPEG·무압축 그림만 직접 꺼내 읽습니다).
빌드 스크립트가 `--collect-all winrt`·`pypdfium2`·`pypdfium2_raw` 로 함께 묶습니다.

### 브라우저

탐지는 Windows 에 기본 탑재된 Microsoft Edge 로 합니다(`channel="msedge"`).
브라우저를 따로 내려받거나 동봉하지 않으므로 `playwright install` 은 필요 없습니다.

## 5. 아이콘

아이콘은 원본 그림 `assets\icon_source.png` 에서 `tools\make_icon.py` 로 생성합니다. 가장자리 찌꺼기를 지우고 크기마다 줄여 ICO 하나에 담습니다. (생성에만 `pillow` 가 필요하며, 실행에는 불필요)

```powershell
.venv\Scripts\python -m pip install pillow
.venv\Scripts\python tools\make_icon.py
```

산출물: `assets\훤히.ico` (16·24·32·48·64·128·256px 포함)

화면 글꼴은 `assets\fonts\PretendardVariable.woff2`(Pretendard 1.3.9, SIL Open Font License 1.1,
라이선스 전문 `assets\fonts\Pretendard-OFL.txt`)를 동봉합니다. 빌드 스크립트가 `assets\fonts` 를 함께 넣으므로
글꼴이 설치되지 않은 PC·폐쇄망에서도 같은 화면이 나옵니다.

큰 그림 하나를 줄이지 않고 크기마다 따로 그립니다. 24px 이하는 렌즈 속 표시를 붉은 줄 하나로
줄이고 테두리를 굵게 해 작업표시줄에서도 뭉개지지 않게 했습니다.

## 5-1. 코드 서명

인증서가 있으면 빌드 스크립트가 끝에 `tools\sign.ps1` 을 불러 자동으로 서명합니다.
인증서가 없으면 서명 단계는 건너뜁니다(`SIGN SKIPPED`).

```powershell
# 인증서(보안 토큰 포함)를 Windows 인증서 저장소에 등록한 뒤 지문을 확인
Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert

$env:HWONHI_CERT_THUMBPRINT = "<지문>"
powershell -ExecutionPolicy Bypass -File tools\build.ps1     # 빌드 + 서명
```

`훤히.exe` 와 서명이 없는 `.dll`·`.pyd` 에 SHA-256 서명과 시각 도장(DigiCert)을 붙입니다.
이미 서명된 파일(Python 재단, Microsoft 등)은 건드리지 않습니다. 추가 도구(signtool)는 필요 없습니다.

## 6. 빌드

> **빌드 전에 실행 중인 훤히를 모두 종료하십시오.** 이전 실행이 남아 있으면
> `dist\` 폴더가 잠겨 빌드가 실패할 수 있습니다.

### 폴더 배포 (제출용 권장)

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1
```

내부적으로 실행되는 명령입니다.

```
pyinstaller --noconfirm --onedir --name 훤히 --windowed
            --add-data "detector\ui\index.html;ui"
            --add-data "assets\fonts;assets\fonts"
            --collect-all playwright
            --icon "assets\훤히.ico"
            --paths detector detector\main.py
```

산출물: `dist\훤히\` (브라우저 미포함)

```
dist\훤히\
  훤히.exe
  _internal\            라이브러리
```

### 네이티브 창 버전 (실험적)

```powershell
pwsh -NoProfile -File tools\build_native.ps1
```

산출물: `dist_native\hwonhi-native-<빌드 시각>\훤히\훤히.exe`

`-OutputName <이름>`으로 출력 폴더 이름을 지정할 수 있습니다. 같은 이름의 산출물이 있으면 덮어쓰지 않고 중단합니다. `_internal`을 포함한 `훤히` 폴더 전체를 배포합니다. 빌드 로그는 `build_native\<이름>\build.log`에 저장됩니다.

`pywebview` 를 포함해 브라우저 창이 아닌 WebView2 기반 자체 창으로 열립니다.

> 서명 없는 `pythonnet` 포함 빌드는 Windows Smart App Control에 차단된 이력이 있습니다.
> 2026-10-17 재빌드한 네이티브 EXE는 이 PC에서 실제 WebView2 창으로 실행됐습니다.
> 다른 PC의 보안 정책에서 실행되는지는 별도 검증이 필요합니다. 차단될 때는 보안 설정을 바꾸지 말고 기본 빌드를 사용하십시오.

### 단일 파일 (참고용)

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_onefile.ps1
```

산출물: 프로젝트 폴더의 `훤히.exe` (약 67MB)

작업 폴더는 `build_single` 로 분리되어 있습니다. 폴더 배포본과 이름이 같아
같은 작업 폴더를 쓰면 산출물이 섞입니다.

단일 파일에는 브라우저를 넣지 않았습니다. 넣으면 실행할 때마다 임시 폴더에 수백 MB 를 풀어야 해
시작이 크게 느려집니다. 이 빌드는 **설치된 Edge 또는 Chrome 이 있는 환경에서만** 동작합니다.

## 7. 검증

## 실사이트 관찰에 따른 실행 안정화 검증

`tools/build.ps1`은 PowerShell 7에서 실행합니다. `-OutputName hwonhi-local`을 지정하면 `dist/hwonhi-local/훤히/훤히.exe`에 생성합니다. 빌드 중간 파일과 전체 로그는 `build/hwonhi-local/`에 보존합니다. 같은 이름의 폴더가 있으면 새 이름을 선택해야 하며, 기존 `dist/`나 실행 중인 이전 배포본을 지우지 않습니다.

`test_scan_control.py`는 localhost의 무한 JavaScript 페이지에서 사용자 중지와 시간 제한을 검사하고, 앞서 완료한 페이지의 결과와 실행 기록 해시를 확인합니다. 별도 자식 프로세스 검사에서 작업 트리 종료와 무관한 프로세스 생존을 확인합니다. `test_scan_ui_controls.py`의 진행 상태는 합성 상태이며, 패널 위치·중지 요청 오류 재시도·입력 보존을 실제 headless Edge에서 검사합니다.

성능 비교는 `tools/benchmark_reaction_wait.py --baseline <수정 전 커밋> --output <새 폴더>`로 실행합니다. 동일한 로컬 페이지에서 끝나지 않는 AJAX와 지연 광고를 사용해 세션의 대기 처리를 비교합니다. 이 수치는 실기관 전체 탐색의 속도 향상률로 확대할 수 없습니다. 전체 회귀·복합 문맥·우회·17초 응답·패키지 EXE 검증을 함께 수행합니다.

설계 근거: 기존 동기 Playwright와 RunArchive를 유지하며, 표준 subprocess의 전용 작업과 원자적 JSON 저장을 사용합니다. 동기 스레드의 취소 플래그만으로 반환되지 않는 브라우저 호출을 중단할 수 없고, multiprocessing의 강제 종료는 자손 종료와 IPC 손상에 별도 처리가 필요합니다([Python 문서](https://docs.python.org/3.13/library/multiprocessing.html)). Windows Job Object로 작업의 자손을 묶고 부모 종료 시 함께 정리합니다([Microsoft 문서](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)).
